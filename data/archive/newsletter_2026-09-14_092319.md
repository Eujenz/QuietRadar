### 專欄破題：Agent 狂歡散場後，留下來的只有管線與交接鏈

這兩週科技圈最吵的聲音，莫過於「Agent 元年」的陣陣號角。掘金熱門榜上《給 AI 的 Agent 實現指南》[¹](https://juejin.cn/post/7667103725047431174)與《Agent Harness 與 Agent Runtime 的區別》[²](https://juejin.cn/post/7679753075939524623)輪番刷屏，彷彿只要套上 LangGraph、定義幾個 Tool，企業級自動化就能交鑰匙交付。但 Simon Willison 卻在自家部落格悄悄釋出 `commit-rewriter`[³](https://simonwillison.net/2026/Sep/14/commit-rewriter/)與 `shot-scraper 1.12`[³](https://simonwillison.net/2026/Sep/13/shot-scraper/)——兩個加起來不足 500 行、專治「AI 寫爛 Commit Message」與「截圖存 WebP」的微型工具，下載數卻遠超那些星標上萬的 Agent 框架。

同樣在 Hacker News Show HN，`1Baton`[⁴](https://1baton.com)宣稱要用 No-code 串起 API 呼叫鏈，`LearnLance`[⁵](https://github.com/aeroscissorz/learnlance/)則試圖從 AI 生成的程式碼中自動抽取知識圖譜。前者直指整合測試的髒活累活，後者盯上程式碼庫裡的隱性知識。這兩個專案沒有講「推理」、「規劃」或「自主決策」，它們只做一件事：**把非確定性的 LLM 輸出，硬生生鎖進確定性的工程管線裡**。

更諷刺的是，掘金另一篇熱文《為啥 Agent 在 coding 表現這麼好，但在別的領域就是差的不少？》[⁶](https://juejin.cn/post/7676901441995391014)給出了殘酷答案：程式碼有編譯器、有單元測試、有靜態分析，擁有世界上最完整的「驗證工作流」；其他領域什麼都沒有。巨頭們不需要發布會，GitHub Copilot 已經在 IDE 內建完成了「寫程式碼→跑測試→修錯誤」的工作流，任何獨立的 Agent Wrapper 都只是等著被 `Cmd+I` 吞噬的暫時性 UI。

這期專欄不聊願景，只算兩筆帳：一筆是 API 整合測試的隱形開銷，另一筆是跨部門交接鏈的破裂成本。

### 案例一：1Baton 闖入 API 整合測試的隱形戰場

`1Baton` 的創辦人在 HN 上的自我介紹很誠實：每天寫 API，單一端點只是大流程的一個動作，測試完整流程得串十幾個請求，資料在請求間傳遞、關聯、驗證，寫膠水程式碼寫到懷疑人生。他要的不是「智慧體」，是一個能「定義一次、複用 N 次、資料自動流轉」的指令碼引擎。這精準踩中了後端工程師最痛的「整合測試維護地獄」。

願景很美，現實卻骨感。目標客戶不是寫 Side Project 的獨立開發者——他們用 Postman Collection 跑跑就好，甚至直接 `curl` 存 Bash 歷史指令。真正買單的是擁有 50+ 微服務、CI/CD 跑 40 分鐘、每次發版都要手動觸發幾十條測試指令碼的中型 SaaS 團隊。他們的現狀偏差不在「沒工具」，而在「工具太重」：Postman Enterprise 年費美元計價、需求部門不給統編不簽約、QA 團隊習慣寫 Python `requests` 指令碼扔在 GitLab CI 跑，誰也不想為了測試專門學一套新的 No-code 視覺化介面。

巨頭的抹殺路徑已經鋪好：GitHub Actions 原生支援 Matrix Strategy 並行跑測試，VS Code REST Client 擴充套件讓 `.http` 檔案成為版控一等公民，更別提 Cursor 現在能直接讀 OpenAPI Spec 生成測試程式碼並自動修復斷言失敗。`1Baton` 若只停留在「視覺化串聯」，三個月內就會被 IDE 內建功能碾壓。

Micro-TAM 怎麼算？全球約 1,200 萬後端工程師，扣除大廠自建平臺、早期創業團隊無預算，鎖定「微服務數 20~200、有專職 QA、年預算 > $50k 工具費」的中型科技公司，約 15 萬家，每家 3~5 名核心測試維護者，可觸達決策者約 60 萬人。替代成本錨定：一名資深 QA 月薪 $5,000（含隱性成本），`1Baton` 若能替代 30% 手寫指令碼維護工時，合理訂價 $29/席/月（團隊版 $199/月）。保守滲透率 1%，年經常性收入（ARR）約 $210 萬——剛好養活一個 3 人核心團隊加雲端帳單，留給創辦人每年 $30 萬現金流的生存空間。

這週末別寫程式碼。去找 5 家符合畫像的公司，發 Google 表單：「請貼上你們最痛的 3 條 API 整合測試流程（OpenAPI Spec 或 cURL 指令），我們 48 小時人工幫你跑出自動化測試報告 PDF，免費。若報告能直接丟進 CI 過關，再談訂閱。」不用寫一行 1Baton 核心程式碼，先驗證「報告能不能直接用」才是真門檻。

### 案例二：賽車隊的 Bot 幻覺與 FDE 的交接鏈陷阱

跨界漫遊帶來一記重擊。《人人都是產品經理》一篇關於 FDE（前線部署工程師）的實錄[⁷](https://www.woshipm.com/ai/6464006.html)，剝開了「裝個 Bot 就能協作」的殘酷真相。北京某賽車隊，攝影師存圖、公關取素材、機械師存知識，全塞進同一個 Bot。聽起來像教科書級的知識管理，實際上卻卡在三個無法用程式碼解決的洞：公關拿到照片能不能直接發？機械師留下的經驗適用於哪種路況？出了事故誰負責確認？

這不是工具問題，是「交接鏈」斷裂。FDE 的價值不在部署了多少功能，在於能不能把「模糊的口述需求」轉成「可驗證的交接標準」。文章現場直擊：老闆只知道預算，員工只知道操作細節，雙方視角都不完整。最有效的做法不是問「你想解決什麼問題」，而是請員工拿真實業務材料，從收到任務開始演示：輸入從哪來、處理後交出什麼、下一關誰接手、驗收標準是什麼。

這對獨立開發者做垂直 B2B SaaS 是降維打擊的洞見。振宇五金賣螺絲做到 22.9 億營收、98 家門市、70 萬會員[⁸](https://www.bnext.com.tw/article/92219/ald-hardware-100-stores-growth-strategy)，靠的不是電商平臺、不是 AI 推薦，是「社群店型」與「自有品牌」——也就是把「找不到規格、買不到現貨、退換貨找不到人」這三個實體零售的交接斷點，全部用「開放式貨架+現場專員+自有品牌兜底」給接住了。他們賣的不是螺絲，是「當你需要 M6x20 不鏽鋼螺絲時，走進巷口 50 公尺就能買到、買錯能換、缺貨會主動通知」這個確定性承諾。

回到軟體。一人公司若想切入製造業、醫療、法務等強合規領域，別再做「知識庫 Bot」或「自動化工作流」了。巨頭的 Copilot、Notion AI、Feishu 已經把「存取知識」變成基建。你的 Tiny Wedge 是：**替客戶把最痛的那條跨部門交接鏈，變成一份「可審計、可追溯、有簽核紀錄」的標準作業程式（SOP）軟體化**。

Micro-TAM 試算：以臺灣為例，製造業中小企約 8 萬家，其中擁有「跨廠/跨部門協作」、「需 ISO 認證」、「年營收 5000 萬~5 億」的約 3,000 家。替代成本：一名資深產品經理或專案經理月薪 12 萬，專職處理交接澄清與追單。若 SaaS 能以「交接不掉鏈」為核心價值，訂價 $15,000/月/廠（含上線陪跑 3 月），滲透率 2%，年收 $1.08 億。但前提是創辦人必須親自進廠，拿著紙本紀錄單、Line 截圖、ERP 匯出的異常報表，和現場主管一起把「交接動作」拆解成軟體強制的欄位與流向。

驗證道具不需要程式碼：準備一份「跨部門交接缺失成本試算表」（Excel），欄位包含：事件描述、責任歸屬模糊導致延遲天數、客戶投訴/罰款金額、內部協調人時成本。這週末約 3 位認識的廠長喝咖啡，請他們填寫最近 3 個月最慘的 3 筆交接事故。若試算出來單次損失超過 $50,000，且他們願意簽名確認「這筆錢若能用系統省下來，我出 $15k/月」，才值得動工寫第一行程式碼。

### 主筆總結：一人公司的防守邊界在「確定性」

這期情報看完，訊號極其清晰：巨頭已經把「智慧」變成廉價基建（Copilot、Gemini、Claude 都在免費額度內塞給你），把「介面」變成作業系統原生功能。留給一人公司的防守邊界，只剩下兩條：

一是 **工程管線的確定性**——像 `1Baton`、`commit-rewriter`、`shot-scraper` 一樣，把非確定性的 LLM 輸出，硬鎖進編譯器、測試框架、CI/CD、版本控制這套鐵律裡，賣「可驗證的正確性」，不賣「可能的智慧」。

二是 **業務交接的確定性**——像 FDE 現場教學、振宇五金巷口門市一樣，把模糊的「溝通協作」硬鎖進「輸入標準、輸出標準、驗收標準、異常升級路徑」這四根鋼筋裡，賣「不掉鏈的 SLA」，不賣「好用的 Bot」。

現金流脫鉤的底線不在「有多少使用者」，在於「客戶願不願意為確定性付費，且這筆費用能不能覆蓋你親自下現場拆解交接鏈的機會成本」。別寫 Agent Framework，寫 Harness；別做知識庫，做交接單。這週末，帶著 Google 表單和 Excel 試算表出門，才是唯一的正事。
